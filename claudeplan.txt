## VisionGuard AI: Build Plan

### 1. Key Decisions (don't let the AI agent change these)

- **AI runs in the browser.** YOLO11n is exported to ONNX and runs with ONNX Runtime Web (WebGPU, with a WASM fallback). The visitor's device does the work, so it's free, and uploaded videos never leave the device.
- **One pipeline.** Every source (upload, webcam, stream, YouTube) becomes a `<video>` element, and the same TypeScript pipeline processes it.
- **Supabase free tier** handles the database, login, roles, evidence images, and real-time alerts. It replaces FastAPI auth and custom JWT code.
- **A small Python Stream Server** (FastAPI, Docker) on Hugging Face Spaces is used only for YouTube/stream relay and plate OCR. It can also run on your laptop through a Cloudflare Tunnel.
- **The frontend is a static site** on Cloudflare Pages or Vercel.
- **Scene Setup per camera.** The user draws calibration points, stop line, traffic light box, and lanes, because speed and violations depend on them.
- **Human review.** Violations start as "pending review". An authority approves or rejects each one.
- **Only violations are stored.** Other vehicles only add to anonymous counts.

### 2. Architecture

text

```text
Upload / Webcam / HLS stream / YouTube (via relay)
                │
                ▼
     <video> → Frame Sampler → Web Worker:
        YOLO11n detect → ByteTrack → Speed (homography)
        → Helmet model / Rider count / Signal color
        → Rule engine → Plate detector (violators only)
                │
     ┌──────────┴───────────────┐
     ▼                          ▼
Stream Server (HF Space)     Supabase
 /ocr  /relay  /media         Postgres, Auth, Storage,
 /probe                       Realtime alerts, pg_cron
```

### 3. Tech Stack

- **Frontend:** React + Vite + TypeScript, Tailwind + shadcn/ui, React Router, TanStack Query, Zustand, Chart.js, onnxruntime-web, hls.js, zod, jsPDF, Vitest
- **Backend:** Supabase (Postgres, Auth, Storage, Realtime, Edge Functions, pg_cron)
- **Stream Server:** Python 3.11, FastAPI, yt-dlp, ffmpeg, EasyOCR, slowapi, Docker
- **ML:** Ultralytics YOLO11, trained on free Colab/Kaggle GPUs, exported to ONNX
- **Hosting:** Cloudflare Pages, Supabase, Hugging Face Spaces, GitHub Actions

### 5. Database

| Table                                      | Purpose                                                                                                                              |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| `profiles`                                 | id, name, role (admin/authority/viewer), settings                                                                                    |
| `cameras`                                  | name, location, source_type, source_url, status, scene_profile_id                                                                    |
| `scene_profiles`                           | calibration points + real meters, speed limit, stop line, signal box, lane lines (solid/dashed), detection zone, enabled rules       |
| `analysis_runs`                            | one processing session: source, progress, fps, totals, status                                                                        |
| `violations`                               | type, vehicle type, plate, OCR and detection confidence, speed, signal state, time, video offset, snapshot/crop paths, review status |
| `traffic_stats`                            | per-minute anonymous counts by type, avg speed, density, heat grid                                                                   |
| `alerts`, `saved_reports`, `activity_logs` | inbox, saved filters, audit trail                                                                                                    |

Turn on Row Level Security for every table. Store evidence in a private storage bucket accessed through signed URLs. A daily cron job deletes old evidence.

### 6. AI Pipeline Logic

- **Sampling:** use `requestVideoFrameCallback` and always use video time, not clock time. Analyze about 8 fps.
- **Detection:** YOLO11n at 640px. Keep person, car, motorcycle, bus, truck, and traffic light. Use confidence 0.35 and NMS 0.5. Treat "van" as a size/aspect-ratio heuristic, since COCO has no van class.
- **Tracking:** ByteTrack with a Kalman filter and two-stage IoU matching. The anchor point is the bottom-center of the box.
- **Speed:** a homography from the 4 calibration points maps the anchor to meters. Speed is distance over about 1 second of video time, median-smoothed.
- **Rules** (each vehicle triggers each type at most once): 
  - **Overspeed:** speed above limit + tolerance for 3 samples in a row.
  - **Red light:** signal box reads red (HSV color count) and the anchor crosses the stop line.
  - **Lane change:** the anchor crosses a solid line. Two or more crossings within 5 seconds counts as aggressive.
  - **No helmet:** the custom model flags no helmet in 60% or more of recent checks.
  - **Triple riding:** 3 or more person boxes overlap one motorcycle.
- **Evidence:** keep the 5 sharpest crops per vehicle. On a violation, make a snapshot. If the vehicle never violates, delete its crops.
- **ANPR:** the plate model runs on the violator's crop. The crop goes to `/ocr` (EasyOCR), and the text is normalized to Indian plate formats (fixing O/0, I/1, B/8 mix-ups). If OCR fails, save with `pending_ocr` and allow a retry.

### 7. Video Sources

- **Upload:** a local object URL, so the file never uploads. Two modes: watch, or batch (fast, with progress bar, ETA, pause/resume). Batch runs in chunks and can resume after a refresh.
- **Webcam/phone:** `getUserMedia` with the rear camera. Requires HTTPS, which the hosted site provides.
- **HLS stream:** played with hls.js. If the stream blocks CORS, it goes through `/relay` automatically. Reconnects with backoff.
- **YouTube live:** the server uses yt-dlp to get the manifest and proxies it with CORS headers.
- **YouTube video:** the server downloads up to 720p mp4, serves it, and deletes it after 2 hours.
- If YouTube blocks the cloud server, point the "Stream Server URL" setting at your laptop through the tunnel.
- **Multi-camera:** grid of 1, 2, or 4 tiles. FPS drops automatically as you add tiles.

### 8. Pages

Landing, Login/Register/Reset, Dashboard, Live Monitor, Analyze Video, Scene Setup, Cameras, Violations (Today/7 days/30 days/Custom), Violation Detail (approve/reject, retry OCR, evidence PDF), Analytics, Reports (CSV/PDF), Alerts, Admin Users, Activity Logs, System Settings, Account Settings.

### 9. Models to Train (Colab)

1. Download a helmet dataset and an Indian license plate dataset from Roboflow Universe or Kaggle, in YOLO format.
2. Train: `yolo detect train model=yolo11n.pt data=data.yaml imgsz=640 epochs=80`
3. Export: `yolo export model=best.pt format=onnx imgsz=320 opset=12 simplify=True`
4. Place `yolo11n.onnx`, `helmet.onnx`, and `plate.onnx` in `public/models/`.

### 10. Laptop Setup (Surface, ARM64)

Install Node.js (ARM64), Git, WSL2 with Ubuntu (for Python and ffmpeg), and Docker Desktop (ARM64). Use the cloud Supabase project for development. Check that WebGPU works in Edge or Chrome by opening `chrome://gpu`.

### Rules for Vibe Coding

- One prompt at a time. Test it, then commit.
- If the AI breaks something, run `git checkout` back to the last commit rather than piling on fixes.
- Keep `CONTEXT.md` updated as decisions change.
- Test with short clips first, then long ones.

### Honest Limits

- Accuracy for night footage, blurry plates, and helmets will be imperfect, which is why human review exists.
- YouTube relay can get blocked. Laptop mode is the fallback.
- Free servers sleep, so the first OCR or YouTube request can be slow.
- Use stock or your own footage. Real enforcement needs official authorization.
