# VisionGuard AI v2

## Overview

VisionGuard AI is an AI-powered traffic monitoring and violation detection platform that runs primarily in the browser using ONNX Runtime Web. The platform analyzes traffic video streams, detects vehicles, tracks movement, estimates speed, identifies traffic violations, generates evidence, and provides analytics through a centralized dashboard.

The architecture is designed to:

* Minimize hosting costs
* Avoid GPU servers
* Preserve privacy
* Scale easily
* Store only violation-related data
* Use free-tier infrastructure wherever possible

---

# Core Decisions (DO NOT CHANGE)

## AI Execution

* All AI inference runs in the browser.
* Use ONNX Runtime Web.
* Prefer WebGPU.
* Automatically fall back to WASM.
* Never introduce a GPU inference server.

## Data Flow

```text
Video Source
    ↓
Browser AI Pipeline
    ↓
Violation Detection
    ↓
Supabase
```

## Backend Rules

Use Supabase for:

* Authentication
* Database
* Storage
* Realtime
* Row Level Security

Do NOT build:

* Custom authentication systems
* Custom JWT services
* User management backends
* AI inference APIs

## Stream Server

FastAPI server exists only for:

* /ocr
* /relay
* /media
* /probe

Nothing else.

## Storage Policy

Store:

* Violations
* Evidence
* Analytics

Do NOT store:

* Non-violating vehicles
* Raw traffic footage

Only anonymous traffic statistics remain.

## Human Review

Every detected violation begins as:

```text
pending_review
```

Authority users must:

* Approve
* Reject

before it becomes an official record.

## Feature Flags

Every AI module must be independently enabled or disabled.

Required flags:

```text
speed_detection
plate_detection
helmet_detection
triple_riding_detection
red_light_detection
lane_detection
alerts
```

Disabling a module must never break the pipeline.
